# P1 — minimal no-shadow Lambda annotations

**Decision under test:** Does the P0 owner graph remain materially small after
adding one real derived responsibility: Lambda evaluation-backed annotations?

P1 remains a throwaway feasibility branch. It does not authorize production
migration, an ADR, or completion of #1236.

## Fixed P0 invariants

```text
application shell owners          1
current Runtime objects           0
current Derived / Watch / Mount   0
current-to-Next bridges           0
cross-runtime synchronization     0
canonical ProjectionCommit Source 1
structural projection transitions 1 for 2 parser updates
```

P0's generic-reconciler and fixture constraints remain unchanged.

## Added graph

```text
ProjectionCommit Source
├─ evaluation Query[Array[EvalResult]]
├─ Registry Query
├─ SourceMap Query
└─ AnnotationMap Query
   ├─ evaluation Query
   ├─ exact ProjectionCommit
   └─ SourceMap Query
```

There is no evaluation Source copied from another runtime. The evaluation Query
runs production `eval_term` from the exact committed projection. The annotation
Query uses the production companion package's existing private annotation
builder and aggregation through a prototype-only visibility adapter; it does not
copy either algorithm.

## Behavioral boundary matrix

| Stage | Required result |
|---|---|
| Initial through structural batch | evaluation and annotations remain undemanded; structural 2 parser updates still publish one commit |
| First annotation demand | evaluation, source-map, and annotations each compute once; registry remains undemanded |
| Repeated annotation demand | all three memo counts remain one |
| Real consumer | production `proj_to_view_node` contains eval and semantic annotations |
| Evaluation-changing edit | append ` 5 2`; one parser publication; annotation changes from `→ ‹closure›` to `→ 3` without a bridge |
| Close | one Region close covers all four Queries and the Source |
| Duplicate close | no lifecycle delta |
| Post-close annotation read | `ClosedRegion`, no provider computation |

## Failure criteria

P1 fails if it requires any of:

```text
current Runtime / Derived / Watch / ProtectedCell
reading escalation_memo
copying a current-runtime value into an Incr Next Source
another application state owner
Program / Port / Manifest framework
persistent annotation closure owner
cross-runtime synchronization
copied evaluation or annotation algorithm
```

P1 also fails if adding annotations makes registry eager, loses memo reuse,
permits mixed projection/source-map inputs, or breaks P0's structural batch
publication count.

## Candidate deletion, not authorization

On success, the virtual ledger may add only these bounded candidates:

```text
present-projection computation in get_annotations closure
Tier-1 direct-evaluation responsibility within escalation_memo
LambdaCompanion memo aliases needed only by that annotation path
annotation-specific constructor wiring
```

Tier-2 escalation, pretty annotations, diagnostics, FFI protection, production
consumer installation, and lifetime closure remain outside P1.
