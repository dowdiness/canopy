## Why this matters

`BTree::from_sorted` computes `max_degree = 2 * min_degree` using MoonBit's
wrapping 32-bit `Int` arithmetic. The current lower-only clamp accepts values
above `Int.MAX_VALUE / 2`; multiplication then becomes negative. For a
non-empty input, the grouping loop can choose `chunk_size = 0`, never advance
`i`, and run forever. Bound the degree before any multiplication and pin the
regression with a test that completes.

## Current state

- `lib/btree/utils.mbt` owns degree normalization.
- `lib/btree/btree.mbt` consumes the normalized degree in `new` and
  `from_sorted`.
- `lib/btree/btree_wbtest.mbt` tests lower-bound clamping but generates only
  small positive degrees.

Current lower-only clamp (`lib/btree/utils.mbt:7-13`):

```moonbit
fn clamp_min_degree(min_degree : Int) -> Int {
  if min_degree < 2 {
    2
  } else {
    min_degree
  }
}
```

Overflow-sensitive construction (`lib/btree/btree.mbt:192-205`):

```moonbit
let min_degree = clamp_min_degree(min_degree)
let max_degree = 2 * min_degree
...
while nodes.length() > max_degree {
```

Existing test boundary (`lib/btree/btree_wbtest.mbt:2255-2263`):

```moonbit
test "from_sorted clamps invalid min_degree" {
  ...
  for d in [-1, 0, 1] {
```

MoonBit core candidates checked:

- `Int::clamp(self, min~, max~)` — reuse this instead of a branch ladder.
- `@int.MAX_VALUE` — reuse this non-deprecated constant to derive the largest
  degree whose doubling cannot overflow.
- `Int64::from_int` / `Int::to_int64` — checked but not needed; widening every
  degree calculation would add conversions while the public type remains
  `Int`.

The applicable repository convention is declarative core code and focused
white-box regression tests; see `lib/btree/utils.mbt:2-13` and the degree tests
at `lib/btree/btree_wbtest.mbt:2239-2288`.

### Step 2: Add the red regression test

In `lib/btree/btree_wbtest.mbt`, extend the min-degree section with a test that:

1. Creates two positive-span items.
2. Calls `BTree::from_sorted(items, min_degree=MAX_SAFE_MIN_DEGREE + 1)` (use
   the package-private constant introduced in Step 3, or the equivalent literal

3. Asserts construction returns, `size() == 2`, `span() == 2`, and
   `btree_invariants_hold(t)`.
4. Constructs `BTree::new` with the same oversized degree and white-box asserts
   the stored degree is the safe upper bound.

**Verify**: `timeout 5s moon test --release lib/btree -f '*oversized min_degree*'`

### Step 3: Clamp degrees into the multiplication-safe interval

In `lib/btree/utils.mbt`:

1. Define a private constant such as `MAX_SAFE_MIN_DEGREE` as
   `@int.MAX_VALUE / 2`.
2. Replace the branch in `clamp_min_degree` with `Int::clamp`, using the closed
   interval `[2, MAX_SAFE_MIN_DEGREE]`.
3. Add a short doc comment explaining that the upper bound exists specifically
   to keep `2 * min_degree` within `Int`.

Do not add a loop or an `Int64` conversion. Add the core/int package import to
`lib/btree/moon.pkg` only if compilation proves it is required.

**Verify**: `moon check --deny-warn lib/btree` exits 0 with no warnings.
